# 平台发布与客户端智能体中心 V1

日期：2026-10-21。用户已批准方案与分阶段实现。发布、执行共享数据库迁移、提交推送另按各仓规则授权。

## 目标与所有权

平台创建 Agent、编辑草稿、发布不可变版本、授权与停用。客户端不创建替代身份，只按设备安装、更新、使用及卸载同一个 Agent ID。平台保留身份、模型池、业务权限与共享知识的权威；客户端拥有安装状态、本机工程与会话。旧市场的角色模板不能冒充平台 Agent。

## 交付阶段

1. P0：两仓规格、ADR、实施任务和兼容/验收矩阵先落盘。
2. P1：平台发布记录、草稿与发布分离、授权下载目录和版本化资源包；平台智能体详情提供发布、停用、版本查看。
3. P2：客户端显式安装状态、分版本资源、下载校验、原子激活、更新/回退/卸载保留数据；所有写入由 Host 完成。
4. P3：主界面智能体中心统一已安装/可安装/更新；移除旧市场设置入口；新会话使用已安装版本。旧会话与工程仍可访问，不能靠重装猜测归属。
5. P4：平台历史发布读取与执行授权；会话固定发布版本，更新不改已有绑定；当前权限、模型池和停用策略每次重新校验。
6. P5：本地 DB/API/真实浏览器完整流程、失败恢复和数据保留；准备 DEV/安装版验收与回滚。在线环境尚未部署时不得标为线上完成。

## 数据与契约

- 平台新增桌面发布状态与不可变发布内容，使用现有 Agent/租户/成员权限；新增 Alembic 迁移，不自动执行线上迁移，不默认发布已有 Agent。
- 管理接口：`/api/agents/{agentId}/desktop-publication`，管理权限可发布/停用；发布携带预览得到的草稿摘要和更新说明，防止发布过期预览。只读使用权限不能发布。
- 桌面接口：`/desktop/v1/agent-distribution`（契约 2.0.0），仅列出可见且已发布 Agent；目录包含发布摘要、版本、包摘要/字节数、兼容要求、当前可用状态。
- 包接口：`/desktop/v1/agents/{agentId}/releases/{version}`。受认证、租户和当前 Agent 权限保护；固定 JSON 文本资源，限制路径、大小与数量，无密钥、二进制插件或任意远程执行配置。通过已授权目录的 SHA-256 验证包字节，真实性来自现有平台认证及 HTTPS；V1 不伪称离线签名包。
- 不改变 1.0/1.1 目录与快照契约；旧客户端继续原流程。新客户端遇到不支持的分发接口显示需要平台升级，不自动退回旧市场安装。
- 每个发布包记录 Agent ID、发布版本、1.1 快照、能力要求、兼容版本和更新说明。桌面外壳版本、Agent 发布版本、制作组件版本分别管理。
- 当前只允许已实现、受控的本地能力；不支持的能力显示具体原因，安装按钮禁用。公共组件可受控复用，私有内容隔离。

## 生命周期与恢复

安装过程：获取当前授权目录 → 下载受限包 → 校验字节摘要、身份及资源路径 → 写入未激活的分版本准备目录（包通过临时文件原子落盘）→ 验证完成 → 原子激活安装指针。任何准备阶段失败都不切换当前版本，不修改已有版本工程或现有会话。单个 Host 内串行处理安装、回滚、卸载；V1 不支持多个独立 Host 同时写同一成员目录。

更新与回退只移动新会话使用的版本指针。会话在首次使用时固定发布版本；旧发布须由平台保留并重新授权执行。停用和权限撤销不能通过旧包绕过。敏感能力增加不静默激活，需明确确认；后台检查与下载不等于授予执行权限。

平台定义与本机工程分目录保存；会话上下文使用固定发布快照。不能向历史工作目录批量覆盖 Skills 或定义，也不自动移动旧成员数据。已有旧快照/绑定保留旧行为，迁移状态明确；卸载只改变安装记录，工程、记忆、历史和已固定版本保留。再次安装复用同 Agent ID 的数据根。

具体落盘：既有 `agents/{agentId}/workspace` 与绑定文件不移动；新版本在 `agents/{agentId}/releases/{sha256}/{definition,workspace,sessions}` 准备定义与工程。安装指针在 `agents/{agentId}/installation/state.json`；会话绑定增加可选 `releaseVersion`。每版独立工程是为避免新 Skills 覆盖仍在工作的旧会话；新版不会自动复制旧工程，旧项目从原会话继续进入，同版本重装复用原工程。后续共享项目能力需单独设计与显式选择，不能靠静默搬迁实现。

第一版使用主动“检查更新”和显式安装，不做静默自动激活。新增能力和回滚到更高能力版本都必须展示目标版本要求并确认。客户端候选外壳版本为 **3.2.0**，平台发布包最低版本相同；当前允许 `core.chat`、`local.files`、`video.production`，视频 Skill 会自动增加视频组件要求。能力清单不授予业务系统权限。

## 验收矩阵

- 管理员创建/编辑草稿 → 发布 V1 → 成员授权目录出现 → 客户端安装 → 开始真实会话。
- 编辑不发布不影响 V1；发布 V2 → 更新 → 新会话 V2、旧会话 V1；回退只影响后续新会话。
- 卸载/重装后旧会话、工程文件及产物逐字节保持；两个 Agent、两个成员、两个主体互相隔离。
- 未登录、只读发布、跨主体、撤权、停用、旧包伪造权限、篡改摘要、路径穿越、链接目录、资源过大、不兼容能力必须拒绝。
- 下载中断、取消、并发安装/更新、磁盘失败、激活前崩溃保留旧指针；本地修改冲突不得被覆盖。
- 既有模型、图片、视频、Website/ERP/SHOP 权限回归；没有真实供应商调用的证据不能标为真实业务通过。

## 工程与检查

客户端：`plugins/fs-platform-access/src/` 与 `test/`；保持 React/Cordis slots 与现有主题，不修改固定上游。`npm run typecheck -w @futurestaff/fs-platform-access`、`npm run test -w @futurestaff/fs-platform-access`、`node --test test/*.test.js`、Profile 构建、真实浏览器及开发客户端验收。

平台：`backend/app/{models,services,api}/`、Alembic、对应 tests，前端智能体详情设置页。`.venv/Scripts/python.exe -m pytest` 跑受影响套件，Ruff、迁移图及本地隔离数据库升级/回滚检查，前端类型/测试/构建。

发布顺序：平台兼容接口及迁移 → DEV 真实流程 → 客户端候选安装版 → 同主体实际任务 → 正式发布。回滚保留新增表、历史发布、旧安装包及用户数据，不自动执行破坏性 downgrade。
