# 3.2.1 凭据锁与登录恢复

用户要求彻底解决记住密码不可用及登录失败，并延续已授权的正式客户端发布。保留当前账号、加密凭据、Profile、全部会话及工程；不重置登录或复制明文密码。

## 根因及复现

实际安装3.2.0，生产Profile。保存密码文件的写锁停留在2026-10-14，锁内为旧PID。protected-secrets读取/has也竞争写锁，10秒后超时；RememberedLogin将读失败泛化为系统加密不可用，登录记住/取消记住操作也被同一锁阻塞。本机Windows加密服务需恢复后实测，不根据提示推断失效。

新增测试首先复现：写入已提交密文后残留写锁，读取超过1秒；第二个用例确认没有独占启动恢复机制。2 failed / 5 passed。修复后9项凭据用例通过，包含真实挂起写操作期间仍读取旧提交、独占权缺失拒绝恢复、PID复用、原密文保持、无关锁不动、链接目录和损坏锁拒绝。

## 修复

- 保留原子重命名写入和写操作互斥；读取及has不竞争写锁。inode变化时有限重试，路径/大小/密文结构校验保留。
- Electron已取得当前userData独占实例锁、尚未启动Host写入者时，恢复仅该目录下规范命名、普通文件、规范PID内容的凭据锁。依据独占启动生命周期，不按文件年龄或PID存活猜测；PID复用也不遗留永久锁。没有独占权时拒绝操作，不修改上游通用锁实现。
- 发版Windows门禁新增完整protected-secrets回归；版本3.2.1，不覆盖3.2.0公开安装包。
